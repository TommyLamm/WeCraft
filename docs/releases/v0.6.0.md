## 新增

- **多層噪音地形**：地表高度改由三層噪音決定——**海陸**（continentalness，決定海陸分佈）、**侵蝕**（erosion，數值越高地形越平坦）、**山脊**（peaks & valleys，用原版的 `1 − |3·|w| − 2|` 折成峰／谷）；**海平面 62**，另有一層氣候噪音（溫度／濕度）決定生物群系。
- **8 種生物群系**：`ocean`（海洋，含沙灘過渡帶）／`plains`（平原）／`forest`（森林，橡木）／`birch_forest`（白樺林）／`taiga`（針葉林）／`snowy_plains`（雪原）／`desert`（沙漠）／`mountains`（山地，92 格以上再依高度分草坡／裸岩／雪頂）。地表材質、F3 的 `Biome:` 與霧色同步（id 對照見 README〈與原版的差異〉）。
- **3 種樹木**：**雲杉**與**白樺**加入（橡木沿用既有形狀）。樹種由生物群系決定：白樺林長白樺、針葉林／雪原／山地長雲杉、平原／橡木林長橡木。雲杉是上尖下寬的錐形、白樺的樹冠窄端在上。
- **地表裝飾**：**蒲公英／罌粟／草叢**（長在草頂，同一柱不會花與草並存）、**仙人掌**（長在沙漠沙面，1–3 格）、**冰**（取代「雪原氣溫」的水面頂端那一格）。
- **cross 型植被渲染**：花與草叢用兩片對角平面（X 形）渲染，**不投影**。
- **仙人掌接觸傷害**：持續接觸仙人掌時**每秒扣 1 點血**（踩在仙人掌上、或跳過仙人掌時身體框與仙人掌格重疊就會受傷；**站在仙人掌旁邊不會受傷**）。
- **舊存檔一次性「地形已改變」提示**：載入舊存檔進遊戲時，右上角跳一次**非模態 toast**（自動消失），並立刻把目前的世界生成版本寫回存檔 → 下次載入不再提示。
- **新方塊的物品形式**：雲杉／白樺原木與葉、蒲公英／罌粟／草叢／仙人掌／冰共 **9 個**都有物品形式 → **可放進熱鍵欄、創造清單可取**。

## 修正

- **樹數暴增（「樹海」）已修正**：樹木密度改為**按生物群系分級的稀疏密度**（候選機率 ＋ 同生態內的優先序局部極小值），並強制**同生態內的樹距**（兩棵樹的 Chebyshev 距離 ≥ 3）→ 不再出現整片樹海；跨生態邊界不保證樹距。
- **地形對比度不足已修正**：地形改為**三層噪音**（海陸／侵蝕／山脊）→ 有了海陸分佈、平原與山脊的起伏、以及高山（92 格以上）的雪頂。
- **新增 `worldgenVersion` 附加欄位**：存檔（本機 payload v3／雲端 format 1）多記一個「這份地形是哪一版生成器生成的」編號（現為 `1`）→ 用它判斷要不要跳「地形已改變」的提示。

## 存檔格式與相容性提示

- **先講最重要的一件：舊存檔在新版載入時，地形會整片改觀。** 本作**從不保存區塊**，載入時是「從種子重新生成整個世界」再套用玩家改動的 overlay → 0.6.0 換了整個地形生成器，所以舊存檔裡的建築可能**浮空、埋入或入水**。首次載入舊存檔會跳一次「地形已改變」的提示。
- **本機存檔仍是 payload v3**：只多了一個**附加欄位** `worldgenVersion`（數字，現為 `1`）；舊版讀到不認識的欄位會直接忽略 → **不需要遷移**，存檔形狀沒有變。
- **雲端進度仍是 format 1**（`readableFormats: [1], writeFormat: 1` 不變）：同樣只多一個**附加欄位** `worldgenVersion` → 0.4.0／0.5.0 的雲端進度照樣讀得出來。
- **0.6.0 寫出的存檔可被 0.4.0／0.5.0 讀取**（附加欄位被忽略）；反過來，0.6.0 讀 0.4.0／0.5.0 的存檔也沒問題（欄位缺漏 → 視為舊存檔 → 跳一次「地形已改變」提示）。

## 已知問題

- **雲端進度的「地形已改變」提示在第一個 checkpoint 之前仍可能再出現一次**：雲端資料要等到下一次 checkpoint 才會帶上新的世界生成版本 → **跨 session** 開機時可能又跳一次（同一個 session 內只跳一次）。**本機存檔不受影響**（本機存檔在提示的當下就寫回新版本）。
- **冰底面與水面頂端共面**：冰取代水面頂端那一格 → 冰的底面與水的頂面在同一個平面上；冰走的是不透明 pass，所以**冰面看不穿冰下、也不遮 AO**。**本次水下視角實測 6 幀連拍未見閃爍**（冰色與水色像素的幀間極差皆為 0）；**但不能宣稱「共面一定沒問題」**——相機在冰面下最多只到 y=61.62，共面區永遠是**掠射角**，且水下 FogExp2 把冰底與水面頂端都染成深藍 → 錄到的畫面**無法分辨**哪一片是冰底、哪一片是水面頂端。根治需要獨立的透明 pass（渲染層改動，不在本批範圍）。
- **仙人掌接觸傷害是「整格判定」**：只有身體框與仙人掌格重疊才受傷 → **站在仙人掌旁的格子不會受傷**（原版是貼框擦邊判定，碰撞形狀內縮 1/16）。
- **cross 型植被佔滿整格**：兩片對角平面貫通整格、整格高（原版是內縮的，約 0.9 格高、短草約 0.8）→ 視覺上比原版略「滿」，貼在牆角時會插進鄰格一點點。這是本批的取捨。
- **「真 worker 路徑 vs 主執行緒」的位元組一致性未驗**：測試用的 `MockWorker` 只回假 buffer，驗不了真的 worker 產出的地形；已驗的是「**worker 失效後的同步退路 ≡ 主執行緒 `generateChunk`**」。
- **霧色切換只做肉眼比對，未逐像素驗證**（出生視線被樹幹擋住 → 只比對了前後截圖的色相）。
- **生成內容的視覺未經自動化驗證**：地形對比、樹形、裝飾密度的證據是**統計測試 ＋ 人工目視**；生成結果是「世界資料」，無法用 CDP 合成鍵斷言。**地形視覺的完整驗證（四方向各走 200 格、逐塊目視）未做**——批末只做 7 個生態各 1 點的取樣（取樣點的 F3 生態標籤 7/7 相符），目視部分仍是人工判讀。
- **出生點的「不可在水裡」保護目前不可達**：以目前的高度公式，出生柱恆高於海平面（**Task 9 驗收**實測 200／400 個種子的出生柱高度最低 **66**，海平面 62）→ 這條路徑屬**預防性程式碼**（若日後調高度公式讓出生點可能入水，它會自動生效）。
- **出生點附近的生物群系受限**：氣候噪音在原點附近趨近 0（出生點的溫度／濕度值都落在 ±0.0034 內）→ **出生點只會是平原／橡木林／山地**（實測 **300 個種子**：plains 125／forest 148／mountains 27；snowy_plains／desert／taiga／birch_forest／ocean 一次都沒出現）→ **雪原／沙漠／針葉林／白樺林需走 24–110 格才看得到**（種子 1337：針葉林 24 格、雪原 46 格、沙漠 52 格、白樺林 109 格）。這是**氣候取樣形式的計畫層級設計產物，不是缺陷** → **世界不會在出生點就給你雪原／沙漠**，玩家得自己走出去探索。
- **跨來源 sandbox iframe ＋ 子目錄的真實瀏覽器驗收已重跑（24 項全 PASS）**：批末驗收在**跨來源** sandbox iframe（父頁 origin `platform.example.test` ≠ 子頁 `game.example.test`）的**根路徑**與 **`/sub/` 子目錄**各跑一輪，涵蓋頁面載入、進入遊戲＋指標鎖、F3 覆蓋層、Esc 暫停／繼續、F5 三態視角、Q 丟棄、資產載入、console／pageerror → **24 項全 PASS**（console error／pageerror／HTTP≥400／requestfailed 全為 0，子目錄變體的 4 個資源全部帶 `/sub/` 前綴）。**未驗證的是「跨來源 iframe ＋ 頂層 Keyboard Lock ＋ 原生全螢幕」的組合情境**（Keyboard Lock 需由宿主頁在**頂層**發起且走瀏覽器的保留鍵路由、原生全螢幕需使用者手勢 → CDP 合成鍵無法複刻，**不宣稱通過**）。
- **批末驗收的其餘未驗證項**：短草叢的逐像素自動判讀（草 tile 與草方塊頂面的線性色度幾乎不可分 → 改以資料證據＋目視佐證）、**凍結海域的水下空間不破冰不可進入**（冰是實心方塊，與原版一致）、0.5.0 ↔ 0.6.0 的渲染量／效能**不可直接比較**（F3 的 `Triangles` 是「讀取瞬間」的值，區塊非同步回傳 → 只記錄不判讀）。連同上面的「地形視覺的完整驗證」「共面 z-fighting 不可宣稱沒問題」「頂層 Keyboard Lock／原生全螢幕」，批末驗收的**未驗證清單共 7 條**（42 項斷言全 PASS／0 FAIL）。

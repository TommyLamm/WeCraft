> B8 箱子與容器持久化：箱子方塊、27 格容器面板、塊實體存檔（箱子內容＋熔爐狀態）。
> 執行計畫：`docs/superpowers/plans/2026-10-20-wecraft-b8-containers.md`；
> 規格：`docs/superpowers/specs/2026-10-18-wecraft-parity-design.md`（§B8）。

## 存檔格式與相容性提示（先讀）

1. **本機 payload 升 v6**（新增 `blockEntities` 欄位＝塊實體清單：箱子內容＋熔爐
   狀態）。**v1／v2／v3／v4／v5 舊存檔照讀並遷移**；舊檔沒有塊實體（那時還沒有
   箱子與可存檔的熔爐）→ 箱子與熔爐的內容讀取後是空的，**不是壞檔**。
2. **雲端格式升 4**（`readableFormats:[1,2,3,4]`、`writeFormat:4`）；舊的 format
   1／2／3 雲端進度會在讀入時自動遷移（塊實體為空、工具補滿耐久、背包補到 36 格），
   下一次檢查點即以 format 4 寫回。
3. **回退限制（雲端）**：0.11.0 寫出的雲端資料是 format 4，**0.10.0（只宣告可讀
   format 1–3）讀不到** → 平台會以 `SAVE_FORMAT_INCOMPATIBLE` 擋下不相容的回退。
   要回到 0.10.0，必須先透過平台支援的相容程序移除／轉換該雲端槽。
4. **回退限制（本機）**：0.11.0 寫出的本機存檔是 payload v6，**0.10.0 只接受
   v1–v5 → 會把這份存檔視為「沒有存檔」**；在 0.10.0 再度儲存會以舊格式覆寫同一個
   IndexedDB 槽。要回到 0.10.0 並保留進度，請先在 0.11.0 匯出／備份。
5. **容量上限**：一個世界最多保留 **512 個塊實體**（箱子 ＋ 熔爐）；單箱 27 格、
   每格最多 64 個（工具 1 個）；超出上限的塊實體不會被存進去；雲端另受 64 KiB
   預算限制（見〈已知問題〉）。

## 新增

- **箱子方塊**（block id 33）：8 塊**同一種**板材排成 3×3 環（中間空）→ 1 個箱子；
  放置 / 右鍵開啟 / 破壞；徒手可挖掉並掉落、斧頭最快（木頭音效）；六面共用一張貼圖。
- **27 格單箱容器面板**：沿用背包的「左鍵整疊／右鍵取一半」游標模型；面板下半是
  玩家 36 格背包；開啟時釋放 pointer lock，關閉（背景點擊／Esc／E）後重新鎖定。
- **塊實體持久化**：箱子內容與熔爐的**內容／燃料／進度**進本機存檔（payload v6）
  與雲端（format 4）；載入時逐筆驗證（壞的那一筆丟棄，其餘照讀）、座標去重、
  筆數上限 512、每格數量夾 `maxStack`。
- **破壞時內容物逐格掉出**：箱子 27 格全滿 → 27 個掉落物（總數守恆）；熔爐的
  輸入／燃料／產物各掉一個；**僅生存模式**（創造模式不灑）。

## 修正

- **熔爐內容重開遊戲不再消失**（稽核項）：以前熔爐狀態只存在記憶體，存檔／重開／
  死亡都會清空（還有「熔爐進度已重置」的 toast）→ 現在熔爐狀態住在塊實體、隨存檔
  保存與還原；**死亡重生不清空熔爐**。
- **創造模式破壞熔爐不再把內容物灑在地上**（創造模式不會撿拾 → 原本會留一地撿
  不起來的掉落物）；箱子與熔爐統一為「內容物只在生存模式掉落」。
- **容器游標在存檔與場次邊界會先沖刷回背包**：面板關閉時「放不下」而停在游標上
  的餘量（以及面板開著時的游標堆疊）現在會在存檔快照前先交還背包（與合成格的
  沖刷同型）；開新局／讀檔／套用雲端時，游標餘量不再跨場次殘留。
- **箱子座標上有另一種塊實體孤兒（雲端還原造成）時不再卡住**：以前右鍵會進入
  容器狀態卻開不出面板（畫面凍結、必須重新載入）；現在與熔爐一致，直接換成
  空的箱子實體。

## 已知問題

- **只有單箱 27 格**：沒有 54 格連體大箱子（兩個箱子不會自動合併）、沒有桶／潛影盒／
  漏斗、不能改名／上鎖。
- **容器沒有 shift 快速搬運**：只能左鍵整疊拿起再點另一格放下、右鍵取一半／放 1 個。
- **箱子的破壞秒數沿用本作通用公式**（徒手 3.75 秒），比原版（13.75 秒）快得多。
- **箱子六面共用同一張貼圖**（原版正面有蓋子與鎖扣的細節）。
- **熔爐的燃料值是簡化表**（煤 8／原木・板材 1.5／木棍 0.5 的「可覆蓋次數」）。
- **雲端同步仍受 64 KiB 上限**：箱子放太多時，該次雲端檢查點會被跳過、
  toast「雲端空間不足，僅本機存檔」——**本機存檔不受影響**。
- **雲端 payload 不帶方塊編輯**：從雲端還原後，箱子／熔爐的座標可能對應不到世界裡
  的方塊 → 內容**暫時取不到**（不會遺失；在同座標放一個箱子／熔爐即可看到）。
- **回退限制**：本機 v6 對 0.10.0 不可讀、雲端 format 4 對 0.10.0 不相容（見上）。

## 存檔格式與相容性提示（請先讀這段）

1. **回退限制（本批唯一的跨版本相容點）**：火把是 **block id 32**，
   **0.8.0 不認識這個 id** → 用 **0.8.0 讀 0.9.0 的本機存檔**時，火把會被顯示成
   **空氣**（`getBlockDef` 對未知 id 落到空氣，**不會崩**）；回到 0.9.0 時火把會
   重新出現（id 仍在 modified overlay 裡，**資料沒有丟失**）。雲端格式未升版 →
   **雲端槽可雙向讀寫**（0.8.0 ↔ 0.9.0 互讀互寫，與本機的火把顯示限制無關——
   體素方塊改動本來就只存本機 IndexedDB，不上傳雲端）。
2. **存檔格式不變**：本機 payload 維持 **v4**、雲端維持 **format 2**
   （`readableFormats:[1,2]`、`writeFormat:2`）→ `game.json` 的 `cloudSave`
   **一字未動**；除上述火把顯示限制外，0.8.0 ↔ 0.9.0 的存檔互通。
3. **光照不入存檔**：光照是導出資料，**載入時重新計算** → 舊存檔載入後的外觀會
   立刻套用新的光照（**洞穴與屋簷下變暗是預期行為，不是資料損毀**）。
4. **火把隨 modified overlay 保存**：0.9.0 存的火把在 0.9.0 讀回時位置與光照完好
   （依附方向不入存檔，載入後由世界重新推導）。

## 新增

- **逐格光照引擎**：方塊光（火把）＋天空光兩條通道，**跨區塊傳播**
  （重算時掃 3×3 群組的來源播種＋BFS）；**生成與載入時計算**，放置／破壞方塊
  後以**區塊**為粒度重算（每幀預算 2 區塊、近→遠排序）；渲染以**頂點亮度＋
  角落平均**平滑呈現，日夜變化只動 uniform、**不重網格**。開闊天空柱 15、
  單格厚屋簷下整列 14、有牆口袋內離洞口每格 −1、密閉洞穴 0、垂直下傳不衰減。
  光照資料每區塊 64 KiB（不入存檔）；出生區 5×5 同步點亮（第一幀正確）、
  其餘可見區塊每幀 2 塊在數秒內點亮；16 區塊「生成＋點光」< 1500 ms
- **火把**：**煤＋木棍 → 4 根**（上煤下棍的 2×1 直排、背包 2×2 即可合成；
  block id 32、tile 39）；**光照 14**（每格 −1 → 照亮周圍 13 格）；只能放在
  **完整方塊的頂或側**（空中放置被拒；不佔碰撞 → 可放在自己站的格子）；
  小型無碰撞模型（2/16 × 10/16 的細柱、貼牆時沿軸貼到支撐面）；挖掉**掉落自身**
  （徒手可收）；**挖掉支撐方塊火把也會掉落**；火把 13 格內**壓制敵對生怪**
- **生怪判準升級為 per-block 光照**（原版判準）：**敵對**需要「內部天空光 ≤ 7
  且方塊光 = 0」——正午地表不再出怪、夜間地表會出、洞穴任何時刻都會出
  （原版行為）；**被動**需要「亮度 ≥ 9」（地表夜間也算，與原版一致）。
  判準逐格（逐隻）檢查，不再整群一起過門檻

## 修正

- **白天與夜晚的地表亮度改由逐格光照決定**：正午地表外觀不變（天空光 15 →
  比例 1.0）；**洞穴與屋簷下變暗**——B5 之前洞穴與地表一樣亮（只有日照／環境光），
  現在挖進地下會真的變暗
- **生怪的「日光下」時鐘近似移除**：B4 的生成判準用 `clockLight(t)`
  （白天滿天空光／夜晚 0）近似亮度——0.9.0 起改為真實逐格光照
  （`spawnLightAt`），`src/world/spawn-rules.ts` 與 `src/world/mobs.ts` 的
  「日光下」近似與註解一併移除（`clockLight` 已全檔刪除）；白天燃燒的遮蔽
  判定（頭頂正上方一格）不變

## 已知問題

- **火把的牆面方向由世界推導**（原版可自由指定牆面；本作依固定優先序
  floor → +x → −x → +z → −z，四面都靠著時取前者）
- **生物與掉落物不使用逐格光照**（仍由場景燈光照亮）→ 黑暗的洞穴裡敵對生物
  仍看得到
- **過濾方塊不衰減天空光**：水／葉／冰在原版讓天空光每格 −1，本作所有透明方塊
  一律不過濾
- **夜晚比原版略暗**：天空光的等級時間無關（與原版一致），但渲染另疊一層
  夜間 0.85 的天空比例；原版的天空比例是每 8 tick 一階的查表，本作用連續插值
- **洞內無火把時接近全黑**（亮度下限 5%，與原版相同）——記得帶火把
- **視距最外緣可能有暗縫**：ring r+1 尚未點亮的區塊邊緣會有一條暗帶，
  **走近即亮**（每幀 2 區塊預算的預期行為，不是 bug）
- **滿群組重算成本**：放置／破壞後的重算以區塊為粒度，滿 3×3 群組約 48 ms／塊
  （效能門檻測試設 100 ms，屬 wall-clock 量測、對機器負載敏感）→ 改動方塊後
  約 5 幀的幀時間短暫升高（挖掘節奏下可接受）
- **夜間地表生怪量比 0.8.0 高**（原版行為，提一句免得當 bug 報）：夜間地表會出
  敵對（內部天空光 4）**也會出被動**（客戶端天空光 15 ≥ 9）；且被動判準比原版
  寬——`max(天空光, 方塊光) ≥ 9` 即可生成（原版在半遮蔽位置還要求方塊光 ≥ 9）
- **瀏覽器層未驗證項**（承襲各批紀錄）：`Ctrl+W` 等瀏覽器保留鍵、平台原生
  全螢幕與頂層 Keyboard Lock 的組合情境、真 worker 位元組一致性——自動化探針
  無法可靠複刻
